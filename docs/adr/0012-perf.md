# ADR-0012 — Performance : cible 100–1000 var × 10–100 Hz, backpressure "pivot pousse / viewer écrase"

**Statut** : acté
**Références** : [spec technique](../spec_technique.md) D24, §13 ; EF-V5

## Contexte

Le viewer peut ramer (rendu draw.io + canvas à haute fréquence) ; il faut définir qui cède : la simulation ou l'affichage. EF-V5 impose déjà que la sim ne rattrape pas par à-coups.

## Décision

- **Backpressure** : le **pivot pousse** toutes les valeurs à chaque pas sans jamais bloquer la simulation ; le **viewer écrase** — seule la valeur la plus récente est affichée, les intermédiaires sont ignorés.
- **Dimensionnement** : cible 100–1000 variables à 10–100 Hz, validée par benchmark en test d'intégration (voir ADR-0003 pour le framing JSON vs binaire).
- Le rendu R3 confine les mises à jour fréquentes aux cellules mxGraph et les courbes au canvas superposé.

## Conséquences

- La simulation n'est jamais pénalisée par l'affichage — cohérent avec EF-V5 (pas de rattrapage, jauge de ratio).
- Côté courbes d'historique, une perte de points est possible si le viewer rame ; elle est inhérente au choix "écraser" et acceptée en V1.
- L'alternative "file bornée + flag de perte" est écartée en V1 (cohérence avec EF-V5, simplicité).
