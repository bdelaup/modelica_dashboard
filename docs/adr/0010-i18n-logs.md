# ADR-0010 — I18n FR+EN dès la V1 ; logs fichier par composant + journal UI

**Statut** : acté
**Références** : [spec technique](../spec_technique.md) D21/D22, §4.2

## Contexte

Langue de l'UI (viewer + éditeur) non tranchée dans le besoin. EF-V6 impose un journal de messages dans le dashboard ; les erreurs techniques des composants (pivot, fonction C) ont besoin d'une trace persistante.

## Décision

- **Langues** : **français + anglais dès la V1**, chaînes externalisées (fichiers de ressources), sélecteur de langue dans le viewer.
- **Logs** : chaque composant (pivot, viewer, fonction C externe) écrit dans son **propre fichier log** (niveaux DEBUG/INFO/WARN/ERROR, horodaté) ; le **journal du dashboard** dans l'UI reçoit les événements métier (variable non connectée EF-V6, erreur de protocole, changement de dashboard, cycle de vie).

## Conséquences

- Toutes les chaînes UI passent par le mécanisme i18n dès le départ — pas de refactor coûteux ultérieur.
- La fermeture du viewer ne perd pas la trace des erreurs côté pivot/simulation (fichiers de log).
